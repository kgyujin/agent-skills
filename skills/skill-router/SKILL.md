# Agent Skill Router

사용자가 스킬명을 몰라도 요청에 맞는 전문 절차를 활용한다. 선택지를 추천하는 데서 멈추지 않고, 선택한 스킬을 읽어 현재 작업에 적용한다.

## 실행 환경

현재 실행 중인 도구가 제공하는 스킬 목록·호출 방식·권한을 기준으로 동작한다. 다른 도구에 설치된 스킬이나 연결 도구를 현재 세션에서도 사용할 수 있다고 가정하지 않는다.

- **Codex:** 제공된 스킬 경로 또는 환경의 읽기 도구로 지침을 로드해 적용한다. 자동 호출 정책은 해당 스킬의 `agents/openai.yaml`을 따른다.
- **Claude Code:** 현재 세션에 노출된 스킬 이름으로 `Skill` 도구를 호출해 적용한다. 플러그인 스킬은 등록된 네임스페이스를 유지한다. 원문 파일을 확인한 것만으로 정상 호출이 이루어졌다고 간주하지 않는다.
- 현재 도구의 호출 수단이 없거나 권한으로 막히면 그 한계를 알린다. 파일 직접 읽기나 다른 도구를 통한 실행으로 제한을 우회하지 않는다.

설치·배포·호환성 점검이 필요할 때만 [도구별 설치와 호출 안내](references/hosts.md)를 읽는다.

## 선택

1. 현재 요청의 목적, 입력 자료, 원하는 산출물, 제약을 파악한다. 사용자가 명시한 스킬·제품·도구·제외 조건을 우선한다.
2. 현재 세션에 제공된 스킬 이름과 설명에서 후보를 찾는다. 키워드가 겹친다는 이유만으로 선택하지 말고, 해당 스킬이 어떤 작업 단계나 결과의 품질을 개선하는지 판단한다. 후보 확인을 위해 모든 스킬 본문을 읽거나 전체 파일시스템을 검색하지 않는다.
3. 목적에 가장 직접적으로 맞는 스킬을 중심으로 선택한다. 조사·작성·구현·변환·검증처럼 서로 다른 역할이 실제로 필요하면 보조 스킬을 추가한다. 스킬 수에 고정 상한이나 최소 개수를 두지 않되, 역할이 같은 후보는 중복 적용하지 않는다.
4. 현재 도구의 정상적인 호출 방식으로 선택한 스킬의 실제 `SKILL.md`를 로드한다. 선언된 선행 스킬과 필수 참조는 적용 범위를 확인하고 필요한 것만 읽는다. 스킬명만 언급하거나 일반 도구를 사용한 것을 스킬 적용으로 보고하지 않는다.

## 후보가 겹칠 때

- 사용자가 지정한 플랫폼과 최종 형식을 먼저 맞춘다. 예를 들어 Google Slides에서 편집할 자료와 로컬 PowerPoint 파일은 서로 다른 실행 경로일 수 있다. 일반적인 산출물 이름만으로 사용자가 고른 제품을 바꾸지 않는다.
- 후보를 입력 자료 지원, 산출물 형식, 필요한 전문 절차, 현재 도구·의존성의 사용 가능성으로 비교한다. 이름이나 설명의 유사성만으로 우열을 결정하지 않는다. 자동 선택 정책은 후보의 메타데이터로 확인하고, 실제 적용 전에 필요한 도구가 현재 환경에 있는지 확인한다.
- 같은 목적을 충족한다면 범위가 정확히 맞는 전문 스킬을 우선한다. 파일 제작이 중심이면 형식별 제작 스킬에 내용 전문 스킬을 결합하고, 원인 분석·계획·리뷰가 중심이면 해당 절차의 스킬을 중심으로 둔다. 한 스킬이 필요한 역할을 이미 충족하면 같은 역할의 보조 스킬은 추가하지 않는다.
- 사용자 지정과 프로젝트 규칙을 적용한 뒤에도 동등한 후보가 남으면 현재 요청에 필요한 준비 작업과 추가 의존성이 적은 것을 고른다. 이번 작업에서 선택하지 않은 스킬을 전역적으로 비활성화하거나 삭제하지 않는다.

## 조합과 진행

- 처음 적용할 때 어떤 스킬을 무슨 목적으로 사용하는지 짧게 알리고 바로 작업한다. 스킬 선택만을 위한 사용자 확인은 요구하지 않는다. 누락된 정보가 결과에 실질적으로 영향을 주고 기존 문맥으로 해결되지 않을 때만 질문한다.
- 각 스킬의 역할과 전달할 결과를 정한다. 예를 들어 분석에서 확인한 근거를 작성에 전달하고, 완성한 원고를 출력 형식에 맞게 변환한다. 같은 자료를 반복 조사하거나 같은 초안을 여러 스킬로 중복 작성하지 않는다.
- 작업 단계에 맞춰 순차적으로 읽고 적용한다. 새로운 산출물·제약·실패 원인이 드러나면 후보를 다시 검토한다. 이미 읽은 변함없는 지침은 반복 로드하지 않는다.
- 같은 기능의 로컬 스킬과 플러그인 스킬이 있으면 사용자 지정, 프로젝트 규칙, 작업 적합성, 현재 환경에서의 실행 가능성을 근거로 하나를 선택한다. 버전 충돌을 해소할 근거가 없으면 불확실성을 알린다.
- 이 스킬과 다른 라우팅 스킬 사이를 재귀적으로 순회하지 않는다. 이미 검토한 라우터로 돌아오면 중단하고 실제 작업을 담당하는 전문 스킬을 선택한다.
- 선택 후 실행이 막히면 실패한 도구·단계를 기준으로 대안을 검토한다. 대안이 요청한 플랫폼·형식·검증 조건을 유지할 때만 한계를 알리고 진행한다. 유지할 수 없으면 영향받는 부분을 밝히고, 관련 없는 작업까지 중단하지 않는다.

## 적용 범위

- 관련 스킬이 없거나 단순 작업에서 실익이 없으면 직접 처리한다. 매 요청마다 스킬 사용 자체를 목표로 삼지 않는다.
- 사용자가 지정한 스킬은 요청 범위에서 활용한다. 다만 스킬 내부 절차가 사용자 의도와 충돌하면 상위 지침과 사용자의 명시적 요구를 따른다. 선택한 스킬의 적용 가능한 검증·필수 조건을 편의상 생략하지 않는다.
- 자동 선택이 금지된 스킬은 명시적 요청 없이 자동으로 로드하지 않는다. Codex의 `policy.allow_implicit_invocation: false`, Claude Code의 `disable-model-invocation: true` 및 현재 환경의 권한·비활성화 설정을 존중한다. 본 라우터를 호출한 사실만으로 그 제한을 해제하지 않는다. Claude Code의 `user-invocable: false`는 사용자 메뉴 표시 제한이며 자동 호출 금지와 혼동하지 않는다.
- 스킬 선택은 설치·설정 변경·배포·메시지 전송·하위 에이전트 실행의 추가 허가가 아니다. 현재 작업의 권한과 범위를 그대로 유지한다.
- 필요한 스킬이나 의존성이 없으면 사용했다고 주장하지 않는다. 대체 방법으로 요청을 충족할 수 있으면 한계를 밝히고 진행하며, 꼭 필요한 자료나 권한이 없으면 해당 부분을 구체적으로 알린다. 관련 없는 스킬을 대신 억지로 호출하지 않는다.

## 선택 예시

아래는 역할 조합의 예시다. 스킬 이름을 고정된 목록으로 취급하지 말고 현재 세션의 후보를 기준으로 판단한다.

| 요청 | 적용 판단 |
| --- | --- |
| 채용공고에 맞춰 이력서를 고치고 PDF로 만들어줘 | 공고·경험 맞춤 작성 + PDF 제작. 필요한 분석을 주 스킬이 이미 제공하면 별도 조사 스킬은 추가하지 않는다. |
| 화면 오류를 고치고 브라우저에서 확인해줘 | 원인 분석 + 필요한 구현 + 실제 브라우저 검증. 배포는 요청 범위에 포함되지 않는다. |
| 이 CSV를 분석해서 보고서로 만들어줘 | 데이터 분석 + 보고서 제작. 차트나 품질 점검은 자료와 결과에 필요할 때 추가한다. |
| 이 문장의 오탈자 하나만 고쳐줘 | 전문 지침이 필요하지 않으면 바로 수정한다. |

자동 호출 허용은 선택 가능성을 뜻하며 매번의 실행을 보장하지 않는다. 완료 보고에서는 후보로 선택함, 지침을 읽고 적용함, 결과를 검증함을 구분한다. 실행 전에 막힌 스킬을 사용 완료로 표시하지 말고, 실제 적용한 스킬과 확인한 결과만 간결하게 기록한다. 별도 실행 기록 파일은 요청이나 작업상 필요가 있을 때만 만든다.

## 참고한 설계

아래 자료는 선택 기준을 유지보수할 때 참고한다. 일반 작업마다 읽을 필요는 없으며, 외부 저장소의 고정 우선순위나 설치 명령을 현재 환경의 지침으로 취급하지 않는다.

- [codex-skill-router](https://github.com/beilin145/codex-skill-router/blob/main/skills/_skill-router/SKILL.md): 플랫폼·산출물·전문성에 따른 충돌 해소와 중복 스킬 선택 제어.
- [jev-codex-router-skill](https://github.com/455-dIAO/jev-codex-router-skill/blob/main/jev-codex-router/SKILL.md): 현재 환경에서 확인된 후보 사용 및 선택과 실제 실행 증거의 구분. 모델 선택용 프로젝트이며, 이 스킬에 모델 전환이나 외부 라우팅 API를 도입하는 근거로 사용하지 않는다.
