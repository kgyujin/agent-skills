# 발표 검수

실제 발표 자료를 만들고 고칠 때 먼저 확인할 문제와 검수 방법이다. 짧은 예제가 보기 좋다고 긴 코드와 실행 화면이 있는 발표에도 같은 배치가 맞는 것은 아니다. 디자인 피드백을 받으면 원본 전체를 먼저 렌더해 보고 색을 바꾸기 전에 정보의 크기와 읽는 순서를 다시 설계한다.

## 1. 본문부터 설계한다

1. 표지보다 가장 복잡한 비교, 과정, 실행 화면 중 두 장을 실제 내용으로 먼저 만든다. 쉬운 표지와 짧은 예제만 검사하고 전체에 적용하지 않는다.
2. 장마다 주된 시각 영역을 하나 정한다. 화면이나 도식이 중요한 장은 본문 폭의 약 2/3를 주고 옆에는 짚을 지점 2~3개만 둔다.
3. 비교표는 `분류 → 기존 → 개선` 순서로 눈이 한 방향으로 움직이게 한다. 강조할 열 하나만 옅은 면으로 묶고 모든 셀에 색과 테두리를 넣지 않는다.
4. 과정은 경로가 주인공이다. 번호, 도형, 화살표, 분기 설명이 같은 말을 반복하면 하나를 뺀다. 읽는 순서와 실제 실행 순서를 대조한다.
5. 코드와 복잡한 그래프가 한 장에서 경쟁하면 나눈다. 생략한 코드는 메모나 부록에 남기고 생략했다고 알린다.
6. 같은 크기 상자가 세 장 이어지거나 제목 아래 작은 글만 떠 있으면 멈추고 레이아웃을 다시 고른다. 테마나 시안 수로 이 문제를 덮지 않는다.

## 2. 캡처와 도식

- 캡처는 실제로 읽히는 크기로 먼저 배치하고 남은 자리에 설명을 넣는다. 읽을 부분을 잘라 크게 보여 준다. 전체 화면은 필요하면 부록에 둔다(`screen` 레이아웃).
- 이미지는 표시 크기의 1.5~2배 픽셀을 확보한다. 작은 원본을 확대 보간해 고해상도라고 하지 않는다. 원본이 작으면 다시 찍거나 한계를 알린다.
- 캡처 속 질문, 상태, 수치를 편집으로 바꾸지 않는다. 원본이 없는 화면을 꾸며 실제 실행처럼 보이게 하지 않는다.
- 도식의 화살촉은 도착 개체를 향하고 되돌아가는 선은 방향이 맞아야 한다. 반복에는 끝나는 조건이 있어야 한다. 원문에 없는 재시도나 승인 단계를 그려 넣지 않는다.

## 3. 짧은 요청에서 시안 고르기

사용자는 자료와 목적만 알려도 된다. 색, 글자 크기, 도형 위치를 질문 목록으로 돌려주지 않는다.

1. 기존 발표를 고치는 경우 사용자가 좋아한 요소와 기존 색부터 지킨다.
2. 새 발표라면 청중, 목적, 자료의 주된 형태(수치, 과정, 화면, 비교)를 파악하고 `--topic`으로 테마를 고른다.
3. "다양하게", "몇 가지 시안", "분위기를 모르겠어"라는 요청이면 구조가 다른 세 안의 표지와 대표 본문을 같은 내용으로 렌더한다. 색만 다른 안은 시안으로 세지 않는다.
4. 사용자가 끝까지 맡겼다면 가장 잘 읽히는 안을 골라 전체를 마치고 고른 이유를 남긴다. 취향을 묻느라 매번 멈추지 않는다.
5. 자료가 적으면 5분 발표도 3~5장이면 된다. 분량을 채우려고 가상의 기능이나 성과를 더하지 않는다.

## 4. 공개 템플릿을 참고할 때

미리캔버스 같은 공개 템플릿이 도움이 되면 목적에 가까운 표지 하나, 비교나 표가 있는 본문 하나, 과정이나 사진이 큰 본문 하나를 본다.

- `관찰한 페이지 | 제목 기준선 | 본문 비율 | 밀도 | 가져올 원리`로 기록한다. 썸네일만 보고 전체 템플릿을 분석했다고 쓰지 않는다.
- 템플릿 파일, 로고, 사진, 유료 요소를 가져오지 않는다. 배치 원리만 네이티브 도형으로 다시 구현한다.
- 사이트에 접근하지 못했으면 그 한계를 적고 이 스킬의 레이아웃으로 진행한다.

## 5. 네 관점 검토

한 작업 안에서 네 관점을 차례로 적용한다. 다른 도구나 에이전트를 실제로 쓰지 않았다면 공동 검토라고 기록하지 않는다.

| 관점 | 확인할 질문 | 고치는 예 |
|---|---|---|
| 발표자 | 어디부터 어떤 순서로 설명할지 보이는가? | 강조 지점을 하나로 줄이고 설명 순서를 메모에 적음 |
| 청중 | 실제 발표 크기에서 글자와 캡처가 읽히는가? | 본문 키우기, 캡처 잘라 키우기, 긴 문단 나누기 |
| 디자이너 | 제목 기준선, 열 간격, 크기 체계, 색의 뜻이 일정한가? | 기준선 통일, 장식 빼기, 반복 상자 재배치 |
| 근거 검토자 | 계획, 실측, 예시가 구분되는가? 원문에 없는 성과가 생기지 않았나? | 숫자 옆에 상태와 단위 표시, 근거 없는 인과 표현 삭제 |

한국어 줄바꿈도 본다. 한 글자만 남은 줄, 조사만 다음 줄로 밀린 곳, 단어 중간에서 끊긴 곳을 고친다. 글이 넘친다고 장마다 글자 크기를 제각각 줄이지 않고 묶음을 다시 나누거나 장을 나눈다.

## 6. 전달 전에

- 고친 최신 파일을 다시 렌더한다. 이전 버전의 미리보기로 새 버전을 검수했다고 하지 않는다.
- 최종 PPTX와 PDF의 파일명, 장수를 기록해 실제로 본 버전을 특정한다.
- 테마에 Pretendard를 지정하는 것과 폰트 파일을 PPTX에 넣는 것은 다르다. 받는 사람 컴퓨터에 폰트 설치가 필요하면 이름을 알려 준다. 라이선스를 확인하지 않은 폰트 파일은 함께 보내지 않는다.
- Google Slides로 옮겨야 하면 글꼴 호환성을 먼저 확인한다. 겉모습 유지가 더 중요할 때만 1920×1080 이상 이미지 슬라이드 복사본을 따로 만들고 편집용 원본과 다르다고 알린다.
- 자동 검사의 오류 0건, 시안 개수, 리뷰어 수를 미적 완성도의 근거로 쓰지 않는다.
