# 분석 발표의 전체 디자인과 편집성

목적: 보기 좋은 한 장이 아니라, 시각 체계가 일관되고 읽기 쉬운 발표 전체를 설계한다. 색·카드·도형을 늘리는 처방으로 단조로움을 해결하지 않는다. 이 지침은 특정 분야의 결과나 다른 발표의 수치를 재사용하는 지침이 아니다.

## 1. 전체 시각 체계부터 설계

이 지침은 글의 주장·문장·분석 논리를 평가하거나 고치는 절차가 아니다. 제공된 내용을 유지하면서 화면의 시각적 위계와 편집 가능성을 설계한다. 제작 전에 다음을 디자인 브리프로 작성한다.

- 사용 상황: 발표 화면인지 인쇄·제출용인지, 화면 비율과 읽는 거리.
- 시각 자산: 제공된 그래프·표·이미지의 크기, 품질, 편집 원본, 사용 범위.
- 전체 시각 방향: 색의 의미, 제목과 본문의 위계, 여백, 정렬 기준, 선과 면의 규칙.
- 참고 디자인: 어떤 페이지의 구도·크기 대비·밀도·이미지 통합 방식을 적용할지.
- 편집 방식: 사용자가 내용을 바꿀 도구와 제공할 원본. PDF만을 편집 원본으로 취급하지 않는다.

이후 `페이지 | 시각적 초점 | 주영역/보조영역 | 사용할 자산 | 정보 밀도 | 앞뒤 페이지와의 시각적 연결 | 편집 원본`으로 시각 스토리보드를 만든다. 본문 순서나 문장을 재작성하기 위한 표가 아니다. 동일 내용으로 배치를 비교하며 어떤 안에서 그래프·표·주석의 위계가 더 잘 읽히는지 판단한다.

## 2. 고정할 것과 바꿀 것

고정할 것은 독자가 자료를 읽는 규칙이다. 제목 위치와 위계, 기준 여백, 본문 크기, 단위 표기, 범례의 의미, 데이터 비교의 색, 표와 그래프의 선 규칙을 유지한다. 표지의 대상 이미지나 기호를 본문에서 의미 있게 회수하면 문서가 하나로 연결된다.

바꿀 것은 증거를 제시하는 방식이다. 연속적인 변화는 추세 그래프, 집단 간 비교는 공통 축, 정확한 조건 비교는 표, 상호 관계는 heatmap, 실제 사례는 대상 이미지로 설명한다. 같은 비교 질문이 이어지면 같은 레이아웃을 반복하는 것이 맞다. 페이지마다 다른 유형을 할당하거나 도형·그래프의 최소 개수를 정하지 않는다.

전체를 펼쳐 보았을 때 핵심 증거가 큰 장면, 세부 비교가 필요한 조밀한 장면, 결론을 정리하는 여유 있는 장면이 내용의 흐름에 따라 구분되어야 한다. 매번 같은 제목·부제·두 카드·하단 요약을 적용하거나, 반대로 임의로 매 페이지 장식을 바꾸는 것도 피한다.

## 3. 증거를 화면의 주인공으로

그래프를 작은 삽화로 넣고 큰 설명 상자로 둘러싸지 않는다. 그래프와 표를 함께 쓸 때 각자의 역할을 정한다. 예를 들어 heatmap은 관계를, 표는 정확한 평균과 표본 수를, 해석 문장은 모델링 판단을 담당할 수 있다. 같은 숫자를 큰 카드·표·본문에서 반복해 공간을 채우지 않는다.

- 비교 그래프: 공통 축과 기준선, 같은 집단의 같은 색을 유지한다. 막대는 원칙적으로 0에서 시작하고 예외는 이유를 명시한다.
- small multiples: 패널별 축과 척도를 통일해 차이를 읽게 한다. 척도를 달리했다면 명확히 표시한다.
- heatmap/교차표: 비율의 분모, 필요할 때 표본 수를 함께 제공한다. 색만으로 값을 전달하지 않는다.
- 분포/산점도: 축·단위·그룹·표본 범위를 밝힌다. 관찰한 관계를 원인으로 단정하지 않는다.
- 사례 이미지: 주제와 연결되는 실제 대상·관찰 장면을 선택하고 강조 위치와 캡션을 붙인다. 장식용 이미지로 증거 부족을 가리지 않는다.
- 결과 표: 조건과 단위를 헤더에 모으고 비교 핵심 열만 강조한다. 수치가 적은 비교는 표만으로 충분할 수 있다.

그림의 목적과 원본 사용 조건을 확인한 뒤 제작 도구를 선택한다. 관측 데이터 그래프에 이미지 생성 모델을 사용하지 않는다. 사용자가 기존 PNG 사용을 지정했으면 재그리기보다 원본을 보존하고 배치·캡션·보조표를 개선한다.

## 4. 편집 가능한 산출물 계약

사용자가 쉽게 바꾸어야 하는 발표는 PPTX를 편집 원본으로 제공하고, PDF는 같은 원본에서 내보내는 흐름을 우선한다. 별도 HTML과 PPTX를 각각 만들어 디자인과 내용이 어긋나게 하지 않는다. 실행 환경에서 같은 원본의 PDF 변환이 불가능하면 그 사실과 미검증 범위를 명시한다.

제목·본문·주석은 실제 텍스트 상자, 표는 native table, 단순 도식은 실제 도형과 연결선으로 만든다. 그래프는 가능한 경우 내장 데이터가 있는 native chart로 만든다. 복잡한 그래프의 SVG는 확대 품질을 지키지만 데이터 편집 가능한 차트와 같지 않다. 이미지로 넣은 요소, SVG, 그룹 도형, native chart의 편집 범위를 구분해 안내한다.

데이터 기반 그래프에는 CSV/JSON 같은 원본과 재생성 경로를 함께 제공한다. 수치·라벨·범례를 수정했을 때 자동 반영되는지 실제로 확인한다. 전체 슬라이드를 한 장의 이미지로 넣은 PPTX를 편집 가능 산출물이라고 부르지 않는다. 브라우저 편집본을 함께 제공하더라도 텍스트만 수정할 수 있는지, 그래프 데이터와 레이아웃도 바꿀 수 있는지 분명히 밝힌다.

## 5. 참고 발표 자료의 전체 디자인을 적용하는 기준

참고한 발표 자료를 전부 펼쳐 보면 흰 바탕, 검정에 가까운 제목, 넓은 바깥 여백, 가는 선, 제한된 비교색이 문서 전체를 묶는다. 완성도를 만드는 것은 많은 장식이 아니라 글과 시각자료의 크기 관계, 같은 기준의 정렬, 페이지마다 달라지는 주영역이다. 아래 관찰은 내용이나 문장 평가가 아닌 시각 디자인 기준이다.

| 구분 | 새 제작에서 적용할 규칙 |
|---|---|
| 표지 | 표지에는 제목·발표 정보·주제 이미지만 배치. KPI·목차·결론을 채우지 않음 |
| 타이포 | 제목의 시작점·폭·기준선을 정하고 문서 전체에서 유지 |
| 바탕과 선 | 상자를 모든 요소에 두르지 않고 선과 면에 서로 다른 역할 부여 |
| 주/보조 영역 | 시각자료의 주도권을 먼저 정하고 보조 요소를 같은 정렬축에 배치 |
| 공통 비교 | 비교 패널의 축·폭·간격·제목 위치를 통일 |
| 밀도 변화 | 조밀한 장과 여유 있는 장을 자료의 역할에 따라 배치 |
| 색의 의미 | 같은 그룹 색을 유지하고 강조색을 다른 의미로 재사용하지 않음 |
| 시각자료 통합 | 이미지마다 독립된 카드 테두리를 추가하지 않고 전체 그리드에 통합 |

이 표를 도형 목록으로 바꾸지 않는다. 제작 전 `바깥 여백 / 제목 기준선 / 본문 최대 폭 / 설명 글자 크기 / 차트 선 / 비교색 / 보조 면`을 한 번 정한다. 그 위에서 한 장의 큰 그래프, 두 패널 비교, 차트+표, 이미지 갤러리, 전체 폭 표처럼 자산에 맞는 본문 구도를 선택한다. 모든 장을 같은 두 카드로 만들거나 반대로 매 장마다 다른 장식을 쓰지 않는다.

절제된 표지와 주제 이미지의 균형은 참고하되, 표지에 분석 요약을 추가하지 않는다. 표지의 시각 소재를 본문에서 다시 사용할 수 있지만 본문 도식을 축소해 표지에 넣을 필요는 없다. 화면상 ‘출처’ 문구나 고정 푸터를 참고 자료에 있다는 이유만으로 복제하지 않는다. 사용자 요청이 없으면 자산 정보는 별도 제작 메타데이터에 남긴다.

원본의 작은 글씨까지 복제하지 않는다. 글자 크기를 줄여 원본처럼 조밀하게 만드는 것은 재현이 아니다. 차트 내부 숫자와 표 라벨을 실제 발표 크기에서 읽을 수 있도록 면적과 페이지 수를 조정한다. 팔레트는 원본을 무조건 복사하지 말고 `palettes.md`의 선별 조합에서 주제와 사용자 선호에 맞게 고른다.

## 5-1. 참고 발표에서 원리만 가져오기

참고 PDF를 받으면 "이 발표를 다시 만들라고 하면 무엇을 지시해야 이렇게 나올까"를 먼저 적는다. 그 지시가 가져올 **원리**다. 도형·색·배치 같은 **표면 형태**는 그대로 옮기지 않는다. 똑같이 만들면 참고 자료의 복제가 되고, 원리 없이 덜어 내면 단조로워진다.

| 참고에서 읽은 원리 | 이 스킬의 구현(다른 형태) | 가져오지 않는 표면 형태 |
|---|---|---|
| 장마다 증거 하나가 화면의 60~70%를 차지한다 | 옅은 무대 위 주인공 증거 + 오른쪽 해석 열 | 같은 크기의 표·도식 배치 |
| 순위·구간은 면의 농도로 읽힌다 | `tiers`: 순위별 농도가 다른 둥근 값 타일 | 한 열을 이어 칠한 파란 칸 |
| 핵심 수치는 진한 면 하나로 시선을 모은다 | `hero-number`·`summary`의 강조색 타일(장당 한 곳) | 네이비 카드 + 주황 숫자 |
| 문제와 해결은 짝으로 본다 | `compare`: 회색 카드와 강조 카드를 행으로 맞춤 | 한 열만 칠한 표 + 삼각형 |
| 과정은 단계와 판단 기준을 함께 둔다 | `flow`: 무대 위 단계 타일 + 여백 열의 기준 | 주황 테두리 기준 상자 |
| 화면 캡처는 볼 곳을 짚어 준다 | `screen`: 옅은 덮개 + 오른쪽 확대 조각 | 번호 테두리 + 주황 원형 번호 |
| 구역과 기획서 항목을 늘 표시한다 | 작은 강조 사각형 + 구역 이름 한 줄 | 칩 모양 태그 + 오른쪽 위 진행 막대 |
| 표지는 주제와 발표 정보만 | `cover split`: 오른쪽 강조색 면의 데이터 모티프 | 네이비 전면 + 짧은 주황 막대 |
| 색마다 뜻이 고정돼 있다 | 회색 = 기준, 강조색 = 우리 값, hot = 경고 | 블루·오렌지 조합 자체 |

**제목은 바꾼다.** 참고 발표의 본문 제목은 "~한다", 부록 제목은 "~했나" 같은 문장형이다. 이 스킬은 발표 제목을 항상 명사형으로 쓰고, 결론 문장은 제목 아래 `lead` 한 줄로 옮긴다. 예: "응답 시간이 2초를 넘는 요청은 재시도율이 3배다" → 제목 "응답 시간 구간별 재시도율", lead "2초를 넘는 요청은 재시도율이 3배".

**너무 단순하지도, 너무 장식적이지도 않게.** 흰 바탕과 가는 선만 남기면 정보가 흩어지고, 칩·배지·띠를 붙이면 촌스러워진다. 면의 농도(바탕 → 회색 면 → 옅은 강조 → 강조)와 숫자 크기로 위계를 만든다.

## 6. 전체 문서와 실제 크기의 두 단계 검수

먼저 전체 페이지를 contact sheet로 확인한다. 시각적 흐름, 표지-본문-결론의 디자인 일관성, 반복되는 불필요한 상자, 밀도 변화, 중요한 페이지의 시각적 무게를 본다. 이어 각 페이지를 실제 발표 크기로 확인한다. 축·범례·표본 수·캡션·글자 잘림·대비·정렬을 읽어 본다. 이미지 안의 작은 글자는 HTML 글자 크기 검사로 검증되지 않는다.

참고 PDF와 제작본의 대응 페이지를 같은 크기로 나란히 본다. 다음을 기록한다.

- 어떤 구도·위계·간격·색 규칙을 가져왔는가? 제작본에서 같은 시각적 효과가 나타나는가?
- 중심 시각자료가 무엇인지 첫 시선에 보이는가?
- 표와 그래프가 서로 보완하는가, 같은 내용을 중복하는가?
- 문서 전체에서 색과 기호의 뜻이 바뀌지 않는가?
- 발표자 설명 없이도 단위·분모·조건을 이해할 수 있는가?
- 실제 편집 원본을 수정한 뒤 동일 PDF로 다시 내보낼 수 있는가?

자동 검사 통과를 미적 품질의 통과로 표현하지 않는다. 시각 검수 결과는 구체적인 페이지와 수정 근거로 남긴다. 재검수는 발견된 문제의 수정 여부를 확인하며, 횟수 자체를 품질의 근거로 삼지 않는다.
